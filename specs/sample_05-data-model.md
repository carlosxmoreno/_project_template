## Entities

### Entity: Invoice
- **Purpose**: represents the structured data extracted from a single PDF invoice.
- **Attributes**:
  - `source_file` (str): original PDF filename, for traceability.
  - `issuer` (str): name of the company that issued the invoice.
  - `invoice_number` (str): unique invoice identifier as printed on the document.
  - `invoice_date` (str): date of the invoice in ISO 8601 format (YYYY-MM-DD).
  - `total_amount` (float): total amount due, numeric only.
  - `currency` (str): ISO 4217 currency code (e.g. EUR, USD, GBP).
  - `extraction_error` (str | None): error message if extraction failed, None if successful.

### Entity: ExtractionResult
- **Purpose**: wraps the outcome of processing a single PDF — either a valid Invoice or an error.
- **Attributes**:
  - `source_file` (str): original PDF filename.
  - `success` (bool): True if all required fields were extracted.
  - `invoice` (Invoice | None): populated if success is True.
  - `error` (str | None): error description if success is False.

## Storage schemas

### CSV output (data/output/)

One row per invoice. Generated by csv_exporter.py.

| Column           | Type   | Notes                                      |
|------------------|--------|--------------------------------------------|
| source_file      | string | Original PDF filename                      |
| issuer           | string | Issuer name as extracted                   |
| invoice_number   | string | Invoice number as printed                  |
| invoice_date     | string | ISO 8601 date (YYYY-MM-DD)                 |
| total_amount     | float  | Numeric amount, no currency symbol         |
| currency         | string | ISO 4217 code                              |
| extraction_error | string | Empty if successful, error message if not  |

Filename convention: `invoices_<timestamp>.csv` (e.g. `invoices_150126_1430.csv`).

## Data flow

PDF files (data/input/) → pdf_extractor → raw text → llm_parser → Invoice objects → csv_exporter → CSV (data/output/).

See 06-pipelines.md for the full step-by-step flow including error handling.

## Design decisions

- **Pydantic model for Invoice**: enables automatic validation of LLM output via pydantic-ai. If the LLM returns a malformed response, Pydantic raises before the data reaches the exporter.
- **extraction_error field in CSV**: keeps errors visible in the output file alongside successful rows, so the finance analyst sees the full picture in one place.
- **ISO 8601 for dates**: avoids locale-specific date format ambiguity across invoice origins.
- **No line items in v1**: deferred to v2. The Invoice model is designed to be extended with a `line_items: list[LineItem]` field without breaking existing CSV output.
